# PersonalVault 2.0 — Интерактивный прототип локального архива документов

Интерактивное одностраничное приложение (SPA) для безопасного управления персональными документами, объединяющее все 18 экранов интерфейса (SCR-01 — SCR-18) и сквозной конвейер обработки файлов в единую систему с общим состоянием и навигацией.

## User Review & Critical Decisions

> [!IMPORTANT]
> На основе ответов пользователя в Фазе 1 согласованы ключевые решения:
> 1. **Архитектура навигации**: Полноценное SPA с общим состоянием и навигацией по боковому меню (без перезагрузки страниц, плавные переходы).
> 2. **Чистота интерфейса**: Верхние тестовые панели переключения сценариев скрыты; отображаются только реальные кнопки действий, контролы и формы пользователя.
> 3. **Интерактивность данных**: Единое реактивное хранилище состояния в памяти (добавление, редактирование реквизитов, завершение планов, восстановление убранных документов, сверка со сканами).

## 1. Overview & Core Concept

**PersonalVault 2.0** — настольно-ориентированная система каталогизации, структурирования и верификации персональных и юридических документов по принципам "Calm Workstation" (спокойная рабочая станция):
- **Локальная автономность**: Все метаданные, сканы и реквизиты хранятся локально (поддержка открытой зоны Open и зашифрованной VeraCrypt Secret).
- **Сквозной 4-этапный мастер импорта и подготовки**: Входящие (SCR-02) → Состав пакета (SCR-03) → Предпроверка качества (SCR-04) → Классификация (SCR-05) → Редактор реквизитов (SCR-06) → Сверка со сканом (SCR-07) → Запечатывание в архив (SCR-08) → Результат (SCR-09).
- **Каталоги и реестры**: Журнал документов (SCR-01), Карточка документа (SCR-11), Черновики сессий (SCR-10), Справочник «Мои данные» (SCR-14), Планы и дедлайны (SCR-15), Убранные документы (SCR-16), Шаблоны схем (SCR-12 / SCR-13), Настройки хранилищ (SCR-17), Центр обслуживания архива и целостности (SCR-18).

## 2. User Experience & Visual Design

### Визуальный стиль и дизайн-система "Calm Workstation"
В соответствии с `DESIGN_9602d240.md` и руководством `frontend-design` (SaaS & Dashboards):
- **Цветовая палитра 60-30-10**:
  - 60% нейтральный холст: `#F4FAFF` (surface), `#FFFFFF` (surface-container-lowest).
  - 30% структурные поверхности и границы: `#E3F0F8` (surface-container), `#D7E4EC` (surface-variant), `#DCE3E5` / `#BDC9C7` (тонкие 1px разделители).
  - 10% акцент: `#006763` / `#298F89` (Primary teal для активных элементов, фокуса, чекбоксов и индикаторов верификации).
  - Статусы: Ошибки/Secret `#BA1A1A`, предупреждения `#E68A00`, проверено `#2E7D32` / `#16A34A`.
- **Типографика**: `Segoe UI` для интерфейса (плотные 12px/13px для таблиц и форм), `JetBrains Mono` для идентификаторов (PV-0042), контрольных сумм SHA-256 и дат.
- **Табличная дисциплина**: Никаких декоративных пилюль-бэйджей в статичном тексте; чистые разделители (`·`), выровненные по сетке tabular-nums цифры, плотность строк 32–36px.

### Основные пользовательские потоки (User Flows)
1. **Просмотр архива (SCR-01 ↔ SCR-11)**:
   - Просмотр каталога документов в табличном или двухстрочном виде.
   - Фильтрация по зонам (Open / Secret), категориям (Жильё, Коммунальные, Здоровье) и поиск (Ctrl+K).
   - Выбор документа открывает боковой инспектор или переход в карточку документа (SCR-11).
   - Из карточки доступен просмотр скана, реквизитов, текстовой выписки OCR, переход к родителю (PV-0041) или перемещение в "Убранные" (SCR-16).
2. **Конвейер подготовки документов (SCR-02 → SCR-09)**:
   - **Этап 1: Входящие (SCR-02)** — выбор файлов или пакета, просмотр превью, кнопка «Объединить в один документ».
   - **Этап 2: Состав документа (SCR-03)** — сортировка порядка страниц (выше/ниже), детальный предпросмотр первой страницы, кнопка подтверждения.
   - **Этап 3: Предпроверка (SCR-04)** — автоматическая проверка целостности файлов, поддерживаемых форматов, проверка на дубликаты SHA-256.
   - **Этап 4: Классификация (SCR-05)** — выбор зоны хранения (Open/Secret), категории, типа документа, даты (точная / неизвестна / отложена), привязка к родителю.
   - **Редактор данных (SCR-06)** — двухпанельный интерфейс: оригинальный скан слева, структурированные поля справа, вставка из «Моих данных», табличные данные оборудования.
   - **Сверка со сканом (SCR-07)** — оптический зум 2.4x с подсветкой координат (BBOX), пошаговое подтверждение реквизитов («Сверено», «Исправить», «Отсутствует», «Пропустить»).
   - **Итог перед сохранением (SCR-08)** — проверка полноты и глубины сверки, AIP-контейнер, модальное подтверждение запечатывания.
   - **Результат архивации (SCR-09)** — экран успеха с паспортом объекта, переход во Входящие или в Журнал.
3. **Управление планами (SCR-15)**:
   - Создание плана получения документа, дедлайны, отслеживание просрочки.
   - Выполнение плана со связыванием с документом из архива (PV-0042) или запуск мастера импорта.
4. **Убранные документы (SCR-16)**:
   - Просмотр обратимо скрытых записей.
   - Восстановление в Журнал одним кликом с сохранением всех связей и целостности.
5. **Справочники (SCR-14 «Мои данные», SCR-12/13 «Шаблоны»)**:
   - Просмотр и редактирование реквизитов персон, адресов, счетов с быстрой вставкой.
   - Каталог шаблонов и визуальный редактор схемы полей (SCR-13).
6. **Система (SCR-17 «Настройки», SCR-18 «Обслуживание архива»)**:
   - Настройка путей хранения, монтирование VeraCrypt, диагностика целостности SQLite, дашборды.
7. **В разработке (DEV-01)**:
   - Модальное окно для функций в разработке («Сводка здоровья», «Помощник»).

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: Единое реактивное состояние в React Context / Hook**:
  - *Выбор*: Централизованный стор `VaultContext`, хранящий список документов, черновиков, планов, шаблонов и справочника «Мои данные».
  - *Почему*: Любое действие (архивация документа в SCR-08, выполнение плана в SCR-15, восстановление из SCR-16, редактирование в SCR-06) мгновенно отражается во всех реестрах, счетчиках бокового меню и Журнале.
- **Decision 2: Нативная компоновка экранов без iframe**:
  - *Выбор*: Полная сборка компонентов на React с чистым Tailwind CSS в едином дереве компонентов вместо изолированных HTML-страниц.
  - *Почему*: Обеспечивает мгновенные переходы между разделами, поддержку горячих клавиш (F4, F5, F10, Esc, Ctrl+K), модальных окон и общее состояние фильтров.
- **Decision 3: Сохранение богатых демонстрационных данных**:
  - *Выбор*: Инициализация стора реалистичными документами из макетов (Акт приёма-передачи PV-0042, Договор найма PV-0041, Счёт Мосэнергосбыт PV-0040, Полис ДМС PV-0039, Квитанция PV-0038).
  - *Почему*: Пользователь сразу видит заполненное, живое рабочее пространство с возможностью протестировать все сценарии.
